## 0. Student folders

Reply in English. `my-docs/inbox/` = student documents (plans, PRDs, user stories, `brief.md`), read-only for AI. `my-docs/specs/` (constitution/spec/plan/tasks), written only via `/my-docs`, is the source for page plans; open `[NEEDS CLARIFICATION]` -> ask, never invent. `my-assets/` is read-only for AI; `pnpm assets` sorts dropped files into icons/images/typo. `my-assets/icons/*.svg` = the only student icon source: copy the named file's exact geometry; missing icon -> ask the student to export it; never draw one. `my-assets/images/` = student pictures, optional: a page uses one only through an approved `{id, image, alt}` item with the exact extension-free name of an existing file (`alt` required, `""` only for a confirmed decorative image); no matching picture -> no image item; never invent, download or placeholder images. `my-assets/typo/` = available font files (Family-Weight names); typography plans pick only these or system fonts. Kit commands: the AI runs them; the student approves (and asks in plain words; `/my-*` is only a shortcut). Deploy: follow `.qwen/commands/my-deploy.md`; the AI runs `node scripts/deploy.mjs` check/setup/publish (and production only after the student chooses it) with shell `timeout: 600000`; the Vercel token goes only into the browser window the script opens and is saved outside the project—never ask for/read/print it, its file or environment variables. Website = `my-website/pages/` only, made by `pnpm ds:page` from an approved plan; never create new top-level folders, a second app, `package.json`, Vite configs or `index.html`. This repo already is ONE React app with routing: `pnpm ds:page` writes approved pages+paths to `web.config.json`; `vite.config.ts` picks the page per URL path; `web:build`/deploy serve every path. "No router" is wrong: never install react-router or any router, never add a workspace/monorepo. Figma page screens: the AI runs `pnpm web:figma [<Page>] "<link>"` itself (never ask the student to type it); it saves `my-website/figma/<Page>.png` (+`.json`, `.layers.xml` structure) for comparison only, never as a page picture.

## 2. Plan -> approval -> implement

Pre-approval: edit ONLY plan. One plan may cover several parts: `components: [Button, Link]` instead of `component:` (any file name). Student picks only some Figma variants -> add `scope_nodes: [<variant node id>, …]` to the header (ids from the pre-analysis Variants list); checks then use only facts from those variants; widening scope = revision++. Hooks: a new plan starts `review-required`/`draft` (never `approved`); the approval edit changes ONLY the `status:` line and is blocked until the plan is ready (facts_complete, open_questions 0, no ask/open/미확정 cells, confirmed Nested parts, design read) — fix that first, never ask for approval before it passes; changing an approved plan needs `status: review-required` + revision+1 in the same edit. `docs/templates/component-plan.md` -> `docs/plans/components/<Name>.md`; pages -> `docs/plans/pages/<Name>.md`. Analysis/cache allowed; no code/CSS/stories/token-input/settings/packages. Record card/version/section IDs, not unread originals.

Plan: sourced facts / AI role-state-event-element interpretations / Q&A choices-impacts. Map states: dimensions/color/alpha/type/border/effects/spacing; icons(presence/path/size/stroke/rotation); tokens(value-role)/API/events/files/tests. Ask every question with `ask_user_question`: <=4 per call, 2-4 options from checked facts only (neutral "Leave it out for now" OK), recommended first + "(Recommended)", Other is automatic; more -> next turn; tool missing/failed -> short numbered list. Record each answer in the plan Q&A as `Q: … → A: … (chosen in chat)`; no invented answers/options/settled repeats. Never ask the student to open/read/edit `docs/plans/**` or `my-docs/specs/**`. Before approval, summarize in chat (~10 plain lines: what is built, decided values (role->color, states, pages/routes/copy), what is left out, 0 questions left), then `ask_user_question` "Approve revision N" / "Change something" (no "(Recommended)"); STOP (PLAN_REVIEW_REQUIRED).

Component source ONLY (never copy source_kind/source_ref into color/typography plans; use their templates and imported-node source_url): `source_kind: figma` (default if omitted) + `source_url`. Adopted starter Text/Icon ONLY: `source_kind: starter-spec`, no source_url, `source_ref: docs/plans/components/<Name>.md`; plan/spec body at that exact path, no symlinks. Same approval/Q&A gates; never substitute for a Figma request.

`starter-fix`: instructor-only audited behavior/accessibility repairs, no visual changes; separate human terminal approval binds plan/CSS/token hashes. Never use for student Figma work or forge/edit instructor records.

Student approves explicit revision only by choosing "Approve revision N" (or typing it); answers to other questions (e.g. "Use these roles"), silence/edits/timestamps/praise do not. Ask after the plan's last change: the hook blocks the status edit until the student chose this revision as it is now, in every approval mode (auto runs tools; it never answers choices). Only then the AI sets that plan's `status: approved` line (no other line) and records the approval; never choose for the student or self-approve. Require real facts_complete=true/open_questions=0; freeze scope/content. Uncertainty: stop dependent work, ask; changed contract: revision++/review-required/reapprove. Never revise a plan just to pass a check: if a check disagrees with the plan or Figma, stop and say "Please show this screen to the instructor." (hooks stop a part after 3 same-kind check failures, and a 3rd revision raise within one student message, until the student writes again). Equivalent internals: no reapproval; unrelated reading OK. Common corrections -> common rules; report affected parts, no unrequested edits.

## 3. Tokens/ownership

CSS: Semantic/Layout only; no primitives, color/spacing/radius/font literals, invented variables, approximations/nearest colors/color-mix. Trace fill/text/border/stroke/shadow value+alpha+role: Figma -> primitive -> semantic -> CSS -> computed style. RGB alone insufficient. Ambiguous mappings: ask; inferred/synthesized: human confirmation. New tokens: use/source, no unused/same-role duplicates. Lookup live definitions.

The AI runs `pnpm ds:figma "<node URL>"` itself (never the student): first Figma link while sample colors remain, a color request, or a part link whose cached Figma variables are missing/changed in `.ds/figma-variables.json` (the prompt hook says "First run …"). The first import replaces sample colors; later imports merge by name (Added / Changed = Figma value wins, roles follow names / Kept) — tell the student those lines in one sentence. A node the hook read in the last 10 minutes costs 0 Figma calls (`--fresh` re-reads); `--replace` is instructor-only. Then empty roles → token plan below, else the part plan. Keep declared Figma roles; infer none. Otherwise propose `docs/plans/tokens.md` via `docs/templates/token-plan.md` (role->student primitive, node/value/reason). `pnpm ds:apply-token-plan --prepare` computes contrasts/hashes, never approves. Only after actual student answers: record decisions, set open_questions=0, `--prepare`, summarize role->color in chat, ask the approval choice (the roles answer is not approval); after "Approve revision N" the AI sets only `status: approved`; `pnpm ds:apply-token-plan` validates hashes, writes mappings/regenerates. No direct .ds edits, stale maps, shared-role repurposing or sample fallback. Missing colors/roles block; unbound colors need exact Figma input.

Mappings without same-name Figma semantic declarations are AI proposals: first draft open_questions>=1; show ONE recommended table in chat (role -> color, reason from Figma names/usage) and ask one `ask_user_question`: "Use these roles (Recommended)" / "Change some roles"; on change, ask only those roles. Record as `Q: … → A: … (AI proposal, chosen in chat)`. Never self-answer, erase questions, or falsely claim "no inference". Node column=imported node number (e.g. 0:1, figma-variables.json nodes), never variable id.

Typography defaults stay unchanged; no plan/work unless requested. To change: `docs/templates/typography-plan.md` -> `docs/plans/typography.md` -> `pnpm ds:apply-token-plan docs/plans/typography.md --prepare` -> chat summary + approval choice (AI sets only `status: approved` after it) -> same command without --prepare. Before prepare, ask with choices "Does the font show as Loaded in Storybook → Foundation → Typography?"; set `font_check: confirmed` only after the student chooses "Yes". Reset: student runs `pnpm ds:reset-typography` directly in an interactive terminal and types the confirmation; AI must not run it. Existing names only; confirm font availability/references/units; no guesses/.ds edits or mixing with color Q&A.

No direct edits: `src/tokens/`, `src/docs/`, `.ds/{tokens,provenance,figma-variables}.json`, `.claude/rules/`; no forged @ds-generated. Check ownership; generate generated stories/Code Connect and approved Figma sets. Owners: Figma=token values/names/variant matrix; code=API; human=semantic/descriptions/guidance. Non-owner changes=proposals. No reverse Figma writes/bidirectional sync.

## 6. Verify/report

Stories: autodocs+real play, fn() click assertions, Tab/focus, BOTH split-button callbacks, disabled non-calls where defined. For approved Nested parts, render each child's real `data-testid` inside the composite root and make the child click call the composite callback in `play`; check Tab order/disabled propagation only when planned. No duplicate/fake static states/hidden focus helpers. Matrix states must be real; replace fake cells with event stories.

Render ALL sizes/states at source copy/scale/dimensions/background. Keep alpha; exact parent background across ENTIRE canvas, not a small card. Preview raw backgrounds need source; never component CSS. Verify iframe background/text/icon visibility, not just backgrounds settings.

Compare computed styles/DOM/screenshots to source color/alpha/type/spacing/borders/effects/icons/ring. Playwright real pointer hover/down+Tab after transitions; userEvent hover/pointer does not prove CSS visuals. play checks behavior. No pixel-diff/invented similarity/tolerance. Font/environment differences need human judgment; unseen screenshots: measurements/paths/limits.

The AI runs `pnpm ai:check <Name>`, `pnpm ai:verify <Name>`, `pnpm typecheck`, `pnpm ds:guard` (G1-G16) itself; the student approves. ai:verify: ALL story render/play errors, not exact equality. Fix failures; record changed causes, no unchanged retries/blind regeneration. Pages ALSO need render/layout/user scenarios+catalog/API/style/dependency checks; component checks insufficient. If `my-website/figma/<Page>.png` exists, page verification includes `pnpm web:compare <Page>`, run by the AI itself, never by asking the student (writes `var/compare/<Page>/index.html`). List visible differences only if you can actually see both pictures; otherwise say you could not see them and ask the student to open the compare page. No match score, no "identical" verdict. No invented page gates; warnings are not approval.

Report task/state/source IDs-versions/parts used-changed/checks passed-failed-unrun/mismatches/missing inputs/pending review; usage actual/estimated/unknown. No stale evidence: match current revision/hash/run; result files need run_id/plan_hash/revision match, zero questions. Hooks are partial gates.

BLOCKED_INPUT: facts/assets/behavior missing. BLOCKED_CATALOG: eligible parts/variants/review missing. BLOCKED_POLICY: contract/ownership conflict. BLOCKED_VERIFICATION: failed/unavailable checks. Report needed inputs; no dependent code or silence/time defaults. READY_FOR_REVIEW: component checks done, human visual/behavior review pending. COMPLETE: all evidence/rules/checks/human review, never budget/retry exhaustion.
